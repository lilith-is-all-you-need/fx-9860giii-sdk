# 2026-11-15 本地验证记录

## Probe 2.1：两份实机回传结论

已收到同一交付版的两份 16384 字节结果，均为 `Build=2.1`、
`IMAGE_BYTES_FNV=00004000,B81796E2`。首份为直接 EXIT 与重入；第二份用户报告
按说明完成菜单选回、EXE、切换其他应用并重入。两份各完成 8 轮自动测试与
第 9 次等待按键前的目标执行，均没有 FAIL/SKIP。

| 证据 | 直接 EXIT | 菜单操作后退出 |
| --- | --- | --- |
| 自动执行、资源/数据/BSS/堆、目标定时器 | 通过 | 通过 |
| 目标退出函数 | 9 次正确调用 | 9 次正确调用 |
| 首次 OS 回调的 active 值 | 0，已由退出路径恢复 | 1，目标映射仍生效 |
| 回调内映射检查 | 不适用 | `CALLBACK_MAP_GUARD=00000000,000000BA` |
| 原映射恢复、清理与日志保存 | 通过 | 通过 |
| 新启动识别已保存回调记录 | 通过 | 通过 |
| 原运行中的 GetKey 返回 | EXIT（30002） | 没有记录 |

第二份关键顺序为 `MENU_READY → OS_CALLBACK(active=1) → TIMER_STOP →
CALLBACK_MAP_GUARD(0) → PASS_TARGET_QUIT → PASS_RESTORE → CALLBACK_CLEANED →
REENTERED_NEW_STARTUP → CALLBACK_OBSERVED`。回调映射检查时计数为 186；该值
反映定时器累计次数，不是菜单等待期间所有瞬间映射状态的连续证明。

结论：本探针 16 KiB BIN 镜像、8 KiB 静态 RAM 的加载、原地址执行、恢复、
两种退出清理与重新启动链路已有实机依据。第一版 Loader 可以采用退出回菜单、
重新打开 Loader 再加载的契约。尚不能证明任意无源码 G1A/profile 转换、KhiCAS
容量及全部系统调用兼容，也不构成长期稳定性或所有 OS 版本的验证。

用户操作说明与日志证据分别记录：第二份缺少 `GETKEY_RESUMED`，不据此指责
操作错误，也不推断回调一定发生在打开菜单、选回自身或选中其他应用的哪一步。
同一次运行从菜单无缝恢复，以及回调的精确触发时刻，仍未确认。

两份实机原始文件 SHA-256（本地保留原始字节）：

- EXIT：`e7f0b7cfe52f0782fc733226665ef75c09238bdfb7c9e9158845968b3e41c45f`
- 菜单：`8fca51b9b20d97bc6a472098d70e3de0fe49d705ec36ba0cebb19926592cac5c`

补充模拟器 `menu-replace + reentry` 独立回归，验证未从 GetKey 返回且 main
尚未返回时执行活动映射退出回调。事件名称顺序与第二份实机文件完全一致；
地址、槽号、时间、MMUCR 动态位不要求逐位一致。原 `menu + reentry` 的恢复
分支仍保留为 HLE 测试，不标为实机已验证。当前 48 KiB 堆下 15 组回归通过，
181 次写入和 131 次定位满足偶数约束，输出在
`probes/emulator/build/probe21-hardware-menu/`。未重编译 G1A，也未修改模拟器
内核；本次证据没有提供足以改变精确菜单触发时机的新信息。

分配返回 NULL 与返回非 P1 地址合并了，且尚未进入映射测试；目前没有实机

旧交付件在模拟器限制 48 KiB 堆时能复现同一画面；**48 KiB 不是实测堆大小**。
