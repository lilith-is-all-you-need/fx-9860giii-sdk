SH3 Add-in 在 fx-9860GIII 上运行：需求收敛与可行性
研究日期：2026-11-18
状态：只读分析与设计建议；未修改 Loader、未生成新兼容补丁、未做新的实机验证。
用户确认的目标：在 fx-9860GIII 上运行原 SH3 Add-in。不是让 Loader 在 SH3 实机上运行。

结论
可以沿用 GIII 单一执行后端，在电脑侧增加旧程序兼容分析和已知例程适配。
不建议为这项目标另起一套 SH3 计算器执行后端，也不需要先做完整 SH3 CPU 模拟器。
但“SH3 指令可以执行”不等于“所有旧 G1A 可直接运行”：程序可能依赖旧键盘、
定时器、LCD、MMU/缓存、OS 私有布局或具体运行库行为。当前证据不足以保证全部自动转换。

一、已核实事实
1. Renesas 官方 SH-4A 资料明确指令级/目标代码级向上兼容 SH-3。
   这是 CPU 层面的依据，不包含 Casio 外设、OS 调用、时序与内存布局兼容保证。
2. fxSDK 作者维护的支持表同时列出 SH3 fx-9860G II 和 SH4 fx-9860G II。
   因此不能只根据“9860II”型号文字判断输入程序的实际硬件依赖。
3. 本地 gint hardware.h 区分 SH7337、SH7355（SH3）与 SH7305（SH4A），
   也区分 I/O 端口键盘扫描与 KEYSC。不要把 SH7705 当成计算器实际芯片；
   其手册是研究相似 SH3 外设/MMU 时使用的参考。
4. 通用 Flash Loader 当前明确针对 GIII：编译参数 -m4-nofpu，使用 SH7305
   UTLB/ITLB、SYNCO/ICBI/OCBP、CPU ID、栈范围和已验证 GIII OS 指纹。
   对当前确认目标，这些依赖应保留，目标程序的旧硬件依赖另行适配。

二、已有无源码适配先例
SH4 Compatibility Tool 的作者发布了源代码、MIT 许可证和问题说明。
它识别特定 fxlib IsKeyDown / IsKeyUp / KeyDown 例程，并替换为适用的实现；
也处理特定 MonochromeLib syscall 调用跳板。它证明“识别已知例程并替换”可行，
不能证明任意编译器生成的自定义硬件访问都可自动替换。
其历史说明将一类失败概括为 SH4 RAM 不可执行；不能把这句直接移植到本项目手册。
本项目已有 P1 可执行探测，应按具体虚拟映射、缓存一致性、权限和跳板放置方式分析。
源工具还提供人为延时以维持旧键盘函数时序；不能简单将这种延时当成无意义开销删掉。

三、建议的三类分析结果
A. 没有发现已知阻塞的旧程序：保留完整原镜像和 CRT，走 GIII 通用 Loader，
   标记“可测试候选”，仍验证输入、绘制、计时、文件 I/O、退出和直接选回。
B. 精确匹配已知旧例程：生成绑定原文件 SHA 的适配记录，记录原字节、补丁位置、
   ABI/寄存器约定、所需 resident helper、额外影子页内存与兼容版本。
   用户测试的 BIN 可继续保持原字节；在影子页实施修补，helper 留在稳定 resident 区。
   不直接复用“向镜像末尾追加代码”的旧工具方式，因为它会更改当前布局/容量承诺。
C. 无法判定或自定义硬件代码：明确列出未解析依赖，不自动猜测地址替换。
   示例：自管 VBR/MMU、直接定时器/灰阶/LCD/键盘端口、动态生成 RAM 跳板、
   通过算术形成硬件地址、依赖固定 OS 内部函数或私有内存。

这些分类需要用“已发现/未发现/未知”表达，而不是自动给所有二进制贴 SH3/SH4 标签。
G1A 不是携带完整架构/重定位信息的 ELF；很多基础指令同时适用于 SH3 与 SH4。
也不能根据工具链目录名 sh3eb-elf 判断程序只能用 SH3：当前 Loader 正是从该工具链
显式使用 -m4-nofpu 构建。

四、库与 profile 的设计边界
执行库统一面向 GIII，PC 端新增可选 compatibility/legacy-sh3 分析模块。
profile 分离：host=GIII；program compatibility evidence；required helper capabilities。
不要向目标伪报 CPU 为 SH3；若旧程序自行检测硬件，应让它看到真实 GIII，
否则原本具备双平台分支的程序反而会走错误的外设路径。
当前 FPF 仅能把已识别的 0x80010070 网关常量替换为 resident gateway，不能表达
通用的旧键盘例程替换。因此新能力需要版本化补丁结构和 resident helper ABI，
不能直接往现有 FPF 假装添加几个地址就宣称支持。
补丁必须逐项检查原字节、指令/PC 相对寻址与延迟槽、目标范围、重复/冲突补丁、
helper 可达性、影子页开销和缓存刷新；不是全局常量替换。
Ghidra 12.2 随包处理器清单含 SuperH4 和 SH1/SH2/SH2A，没有可直接选用的 SH3
语言 ID。目前固定的 SuperH4:BE:32:default 可以帮助分析共同指令，但不是自动
SH3 识别证明；若需严格 ISA 筛查，另设已核实的指令允许表/验证器。

五、最小可验证推进顺序
1. 收集用户真正想运行的旧 SH3 原始 G1A；逐一记录在 GIII 上直接运行的结果。
2. 用相同字节进行“原 OS 直接启动 / 现 Loader”对照，分开记启动、按键、画面、
   计时、文件访问、MENU 直接选回与 RUN-MAT 后新启动，防止把原生不兼容归给 Loader。
3. 先实现一种已知键盘例程适配：无键盘补丁对照、精确模式、字节轻微变化必须拒绝、
   4 字节对齐差异、helper 回调期间映射稳定性等自动回归。
4. 模拟器验证之后在 GIII 实机确认；记录补丁版本和输入 SHA。验证成功只能扩展到
   同一已核实例程合同，不推广到所有 SH3 程序。
5. 再评估 MonochromeLib 跳板与更复杂的灰阶/计时器程序。未知 MMIO 不自动放行。
