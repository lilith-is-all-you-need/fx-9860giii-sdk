# 经验怎样进入新的 SDK

## 已采用的工程措施

| KhiCAS 中的教训 | 本次落地位置 | 验收方式 |
| --- | --- | --- |
| Windows 源码、VM 副本和旧产物身份混淆 | engineering.py snapshot/compare | 同长度内容修改、文件新增/删除都能检测；只报告不回滚 |
| 把可用存储、MB/MiB、保守预算混成硬上限 | budget.json + budget 命令 | 整数字节、依据、余量；报告明确不等于实机兼容 |

| 文档版本号和实际源码漂移 | 模板同步器、来源哈希和打包检查 | canonical scaffolds 与 skill assets 逐文件一致 |
| 将旧模板的高优化参数用于 Debug | CMake 不强制 -Os/-flto | 保留 SDK 的 Debug/Release 流程和源码断点 |
| 打包后丢了新脚本/说明/模板 | skill、完整包与源码包收集入口 | 新文件列入包清单，独立 skill 包可创建工程 |
| 模拟器能跑等同硬件通过 | skill 边界与模板报告 | hardware 永远不由预算/宿主检查自动变成 pass |

## 容量记录的更正

KhiCAS 用户在 fx-9860GIII / OS03.70.0200 报告原版 2,094,444 B 可打开；
旧诊断 2,000,000 B 可打开，2,859,592 B 不识别。这只提供已知样本，
没有确定精确 OS 识别边界。2 MiB = 2,097,152 B，不等于 2,000,000 B。

**本 SDK 现有构建校验器仍采用 2,000,000 B 的暂定部署预算。**
这次经验迁移不修改其运行时/发布兼容性合同。新模板增加 16,384 B 的工程余量，
它是可配置政策，不是设备事实；只提高 budget.json 不能绕过 SDK 校验器。
旧 docs/KHICAS-REUSE.zh-CN.html 保留为历史调研，并增加了更正入口。

## 内存与 ABI 不能直接搬参数

KhiCAS 的 32 KiB 池、24 KiB 跟踪门限和额外 8 KiB 模块窗口属于该实验配置。
不同启动代码、OS、gint 状态、静态区和运行库会改变可用内存。
新模板只承诺自己管理的 512 B scratch，不声称全局 malloc 有上限或整个设备不 OOM。

当前 SDK 的 C++17 示例、标准容器和正常 RAII 已有有限验证，但异常和线程不在支持
范围。不要把 Giac 的全局 new/delete、异常帧注册、uSTL/libstdc++、旧 libfx 或
TomMath 分配拦截粘入普通模板。它们必须作为独立平台移植，拥有匹配 ABI/启动/错误路径。

## 保留在进阶研究区的经验

- 动态代码：D-cache 写回、同步、I-cache 失效的实机问题确实发生过；现模拟器不模拟
  物理缓存。这一事实只作为调试线索，没有把加载器或 SH7305 专用指令并入通用模板。
- 外部文件：能 BFile 读取不等于文件可作为稳定执行映射；分页也有常驻成本、
  活动调用、异常展开、悬空指针与失效问题。
- 错误恢复：C++ 抛异常不自动撤销全局符号、共享堆或 C 库状态；longjmp 不能替代
  C++ 析构。新示例用显式状态码与短期字节缓冲，不宣称解决了任意对象图的回滚。
- 速度：必须固定输入、输出、配置和设备比较；本次未声称新 SDK 或模板比原版更快。
- 来源与许可：只迁入经验文本，新增辅助代码独立按 MIT 编写；没有将缺少独立许可
  的原 CAS 源码改名后纳入 SDK。

## 与现有 SDK 特有问题合并阅读

原生工具链仍须处理中文/撇号路径、构建输出互斥、LTO zlib/zstd 兼容、
-nostdlib 下显式 stdc++ 链接，以及 WPF/Agent 合并发布时 WindowsBase 覆盖。
这些已有说明见 [构建手册](../BUILDING.md)、[原生编译器](../../tooling/native-sdk/README.md)、
[C++ 探针](../../probes/emulator/cpp-runtime/README.md)。不要以新模板替代现有发布验证。

自动化提交成功不等于操作完成；重试用相同 requestKey，等待终态，停止自己拥有的会话。
每个任务使用独立 state 与构建目录，bridge.json 属本机凭据，不进快照或归档。
