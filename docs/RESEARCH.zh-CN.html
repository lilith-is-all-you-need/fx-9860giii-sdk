Fx Studio · 开发工具调查 · 2026-11-14

现有工程、离线部署与调试预览

目标是开发最终能交给 fx-9860GIII 的 C/C++ 插件。计算器接收的是 .g1a 文件；SDK 与 IDE 运行在电脑上。

1. khicas-addin 包含什么

它是一套使用 fxSDK / gint 的 KhiCAS 应用工程，并不是完整 SDK。正式 CMake 入口有 COMPACT 与 NUMERIC 两种后端；较新的 Giac、异常运行库与大型链接实验还分散在 tools / audit 中。普通 C/C++ 开发不应默认采用这些实验配置。

内容作用对新 IDE 的意义
src、assets、CMakeLists.txt计算器入口、界面、Compact CAS、Giac 适配、图标可作为真实应用与回归样本
tests主机算法测试、按键和像素回归、SuperH 探针可保留，但主机预览和 QEMU Linux 探针不能代替最终 G1A 仿真
tools、audit构建恢复、链接、体积、运行库、符号与发布检查包含机器固定路径和实验状态，不能直接包装成通用 SDK
dependenciesGiac 等源包和基本 Ubuntu 镜像缺编译器及宿主完整依赖闭包
releasesCAS01/CAS02 等候选、源码快照与历史验证可以验证历史程序，但不能冒充新 IDE 已重新构建

本机可确认的稳定工具版本为 fxSDK 2.11.0、GCC 14.1.0、binutils 2.42、gint 2.11.0，配合 fxlibc、OpenLibm、libstdc++。原恢复 WSL 环境缺少 CMake、Pillow、部分模块和宿主库；只复制 bin 或项目目录无法离线开发。

2. 能否完全离线部署

技术上可以。编译、链接、生成 G1A、模拟器和 GDB 都不需要在线服务。必须把版本固定的编译器、目标头文件/库、CMake、资源转换器、Python/Pillow及许可证、源码一并准备好，并在新目录中验证。外部下载依赖的 CMake 项目需先把依赖纳入工程。

最初选用独立 WSL1 发行版保存完整 Linux 工具链。本机 WSL 全局服务随后挂起，且当前进程无服务重启权限；用户要求暂不重启。因此没有把未导出的 rootfs 标为已交付离线镜像。现已完成原生 Windows 后端，使用同版本 SuperH 编译器与目标库，绕过 WSL 服务；新 C/C++ 四种配置及整包搬移验证均通过，详见交付验证记录。

对外发行只包含可再分发组件。官方 Casio SDK、官方模拟器、Casio ROM、个人 Linux 目录和历史 KhiCAS 测试件不混入公开运行包。GNU 组件保留对应源码、构建脚本和许可证；GUI 的自包含 .NET 运行时保留微软原始通知。

3. 能否像 C:\9860 一样“所见即所得”

可以实现运行时屏幕与按键，并与源码调试同步。这里按用户定义采用运行预览，不是拖放式界面设计器。源码在同一模拟会话中断住时，右侧画面来自已经执行的 SuperH 程序，而不是 Windows 上重新编译的界面替身。

官方 SDK 的本地帮助确认了工程编辑器、计算器屏幕、源码/地址断点、条件与读写访问断点、单步进入/越过/返回、变量、栈、寄存器、内存及反汇编。其默认编译参数为 SH3，不能据此推断能完整模拟 GIII。官方 GUI 截图在本机捕获超时，功能依据其本地帮助与官方指南核对，未反编译或分发专有程序。参见 Casio 官方 SDK 入门指南。

4. 实际实现的设计

层实现选择原因
桌面 IDEWPF + AvalonEdit，中文/英文，原生 Windows 控件，轻量 Fluent 风格编辑体验完整，不带浏览器内核；自包含包无需先安装 .NET SDK
构建原生 Windows 或独立 WSL；CMake、GCC14.1、fxSDK/gint复用标准 C/C++ 工程，Debug/Release 分离，原源码不被构建适配器修改
调试器独立 GDB 16.3，MI2 连接 IDE，远程协议连接模拟器变量/栈/DWARF/单步由真实调试器处理
执行和预览MIT 许可 emuCasioCalc 的 GIII 类 SH7305 配置，加 Windows 调试桥直接执行最终 G1A；不依赖 Casio ROM
一致性逐段对比 ELF 物理加载地址与 G1A payload，复核 SHA-256拒绝旧 ELF 搭配新 G1A，避免错误行号和变量伪装成正确调试

Debug 的用户源码用 -Og -g3 -fno-lto 编译；预编译 SDK 库中存在精简 LTO 对象，最终链接仍需启用 GCC14.1 的 LTO 插件。库本身的优化限制会明确显示为 <optimized out>。C++ 基线支持模板、RAII 和容器，默认不支持异常和线程，不混入 Giac 的自定义 SJLJ 运行库。

已取得的真实证据

CAS02 的实际 G1A 在原生模拟器中接收 2 + 2 EXE 并显示 =4。CAS01 找到完全匹配的历史 ELF，三个非空加载段、105,288 个 payload 字节逐一对应，完成 main 断点、局部变量、ui_draw → main 调用栈、next/step/finish 与停点画面变化。相同 ELF 搭配 CAS02 被校验器拒绝，首个差异位于 0x0030022A。

WPF 界面实际接入该会话，在 main:78 停住并显示 Starting CAS；执行行高亮、局部变量和右侧画面来自同一会话。协议、坏输入、取消、并发释放与源文件暂存也有独立检查。随后新工具链的 C/C++ 四种配置也分别完成构建、按键、屏幕与调试验证；历史包与新编译产物的证据分开保存，详见交付验证记录。

明确边界

  • 模拟器不等于完整 Casio OS：内置菜单应用、USB、部分外设和 DSP 算术指令尚不完整。未知指令/调用应报错。调试查看 MMIO 会拒绝，避免读寄存器改变设备行为。
  • 运行速度并非周期精确；暂停会冻结模拟 CPU 和时间，按键只能在运行时输入。
  • 当前没有连接真机。设备识别、安装、OS 差异和实际硬件行为需要人工检查。电脑端远程调试不能代替这一步。
  • 依据新增设备反馈采用完整文件 2,000,000 字节的保守 G1A 门禁，这是工程经验限制，不声称是已经证明的所有 Casio OS 精确上限。大型 Giac 容量问题不会被 IDE 自动解决。
