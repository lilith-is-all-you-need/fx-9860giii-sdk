Fx Studio：当前源码的 SDK、资源与调试支持范围

更新于 2026-11-18。本页描述当前源码；原 0.2.0 ZIP 的历史验收见 发行验证报告。后来增加的 Loader、系统调用、fxlib 兼容层和资源导入需要重新构建并组装，旧 ZIP 不自动升级。本页区分源代码实现、已构建产物和真实设备证据。

1. Casio 系统调用

实现了可用子集，没有完整模拟 Casio OS。当前源码覆盖表记录 164 个注册入口：146 个具有处理代码、12 个部分实现、6 个占位。注册数不等于完整实现数，也不是覆盖率。详见 覆盖说明。未知调用报告错误；占位入口可能不产生实际效果。该层运行旧二进制，与让旧 C 源码通过编译的 fxlib 兼容库是两件事。

光标/重复键控制、关机和部分退出处理仍有简化；系统菜单、USB/真实串口没有完整实现。BFile 映射为宿主文件，模拟容量 16 MiB，部分非 ASCII 设备文件名被替换。当前默认硬件模型报告 03.70.0200，默认堆预算 192 KiB；khicas/probe3 压力配置为 48 KiB。它们不能替代实机内存测试，也不代表真实最大连续可分配容量。

模型实际使用上游 MODEL_FX9750G3 的 SH7305 单色平台配置。历史报告引用的 DisplayMainMenu 0x1E6A 属于 CG 表，不能当作 GIII 调用号；GIII 系统菜单不完整的结论来自 FX GetKey 的 MENU 处理与真实重入测试。

2. gint 内部复杂绘图

这些绘图函数作为 SuperH 代码在模拟器中执行，最终由模拟 LCD 显示。新探针使用发行包编译了 35,340 字节 G1A，完成 ELF/G1A 全部载入字节配对；裁剪、多边形、圆、椭圆、越界线、透明图片与局部图片、自定义位图字体七项检查全部通过，并确认四档灰度显示和退出灰度恢复。

灰度预览现在有实际验证证据；它仍不等于真实 LCD 的闪烁、响应时间或速度测量。gint/image.h 的通用旋转、缩放和 RGB565/P8/P4 操作目前主要面向 fx-CG，不能直接当作 fx-9860GIII 能力。未宣称验证了所有参数组合、3D 引擎或所有字体编码。

3. fxSDK 与旧项目

离线 G1A 核心构建链路完整可用，fxSDK 命令套件并不完整。包含 GCC/binutils、gint/fxlibc/OpenLibm/libstdc++、CMake/Ninja、fxgxa、fxconv、Python/Pillow 和 fxSDK CMake 模块。fxsdk.exe 是提供路径/版本查询的原生适配器，没有完整上游 new/build/send/install 命令，也没有 fxlink、完整 GiteaPC 或 USB 传输工具。

CMake+gint 工程最容易迁移。当前新增公共 compat/fxlib 源码兼容子集，以及“工具 → 迁移旧 fxlib 工程”：复制旧源码、配置 CMake 和可选 AddIn_main 入口，并生成迁移报告。详见 迁移与资源指南和API 支持矩阵。支持范围内的源码可保留旧调用；SHC 汇编、直接 syscall、旧二进制库、不支持的 API 和字体/定时语义仍需适配。它不是完整官方 fxlib，fxlibc 也不是 fxlib。历史俄罗斯方块移植仅为项目专用先例，未随新公共库发布原游戏。

4. 资源导入、转换与压缩

“工具 → 导入资源”支持旧 fxlib 单色位图、gint 图片和二进制数组，自动复制输入、生成 project_assets.h 并接入 CMake。命令行 tooling/project_assets.py 还支持带网格参数的位图字体。旧位图输出逐行高位在前的 C 数组，gint 图片/字体使用 fxconv；两种结构不能直接互换。多目标工程须明确目标，重复导入检查内容和符号冲突。自定义转换器及高级格式仍可直接维护 fxconv 配置。

未提供通用自动压缩、TTF/OTF 字体栅格化或资源 RAM/ROM 用量面板。自动选择较小颜色/位平面格式不等于 RLE/LZ 压缩，PNG 文件小也不意味着编入程序后的资源同样小。动画编辑、地图/音频专用管线仍不在支持范围。资源工具的具体参数和限制见迁移指南。

5. 资源预览

0.2.0 增加 PNG/BMP/JPEG/GIF/TIFF/ICO 的只读源图片预览，支持尺寸、字节数、透明棋盘和整数倍放大；多帧文件明确只显示首帧。未知二进制仅显示文件信息，不能误当源码保存。

这仍是源文件预览：未提供转换后 bopti、字形表、动画、压缩前后对比或资源 RAM/ROM 用量面板。程序运行画面可以验证最终绘制效果，但需要构建和运行。

6. 人类使用的调试界面

0.2.0 补充双语暂停原因与当前栈帧、运行时旧变量提示、操作状态禁用、指令单步、断点启用/禁用及持久保存；刷新保留检查器页。屏幕可单独整数倍放大并保存原分辨率 PNG。源码缺失或一个读取项失败时，其余检查项仍能继续显示。

现有断点、监视点、源码/指令单步、调用栈、变量、寄存器、内存和反汇编可用。体验仍不是成熟 Visual Studio 的全部能力：没有反向调试、完整执行历史、性能分析和完整容器可视化；预优化 SDK 库内部源码/变量也可能不完整。

7. Loader Suite 0.2 与源码迁移的区别

Profile Studio 0.2 与 profile_job.py 生成 FXAPPS/<程序ID>/ 目录包，默认只导出程序依赖，可选或独立导出公共启动器。普通 Flash 后端由 FlashLd.g1a 扫描目录；Full 为默认，Fast 依赖此前成功的完整校验，可能漏检两次启动之间同大小的内容变化。旧 loader_suite.py 保留历史平铺格式。目录和安装约定见 Loader 中文手册及English guide。

源码接入的大程序使用 FxStudio::LargeRuntime 与 ExtLoad.g1a 的动态页表；原版 KhiCAS 仍有专用适配器。未知超限二进制、任意旧 SH3 程序与通用调用者栈/堆恢复均不保证；Ghidra 的位置和指令证据不自动授权可执行补丁。调用者业务会话库有事务及 MENU 策略，当前通用 Flash 后端缺少返回能力时明确拒绝。这些二进制部署机制不替代前述 fxlib 源码兼容层。

验证范围分别见 fxlib/资源验证和Loader 0.2 独立验证。前者分别保留合并前结果与 c61d1c8 完整本地包的组装、双语 IDE 和 Agent 实际目标复验；没有把旧组件测试改算为新包测试。历史实机首次启动反馈不等于新目录版、动态运行库或兼容库已通过实机验收。

稳定的 LLM 调用设计

新增自包含 FxStudio.Agent.exe --stdio，使用标准 MCP。固定四个外层工具分别负责发现、提交、操作查询/取消、事件读取；具体功能放在有独立版本与参数 schema 的命令目录中。构建/调试业务位于独立 Automation 层，底层继续使用 Core，协议不侵入 GDB 实现。

包含会话、幂等请求键、异步操作、稳定错误码、事件游标/丢失提示、暂停状态快照及实际 PNG 画面。运行态不伪造同步变量；任意表达式求值显式标记为可能修改目标。新增兼容功能扩展目录与可选字段，破坏性变化必须升版本。完整约定及调用示例见 AUTOMATION.md。

当前自动化拥有独立会话，还不能接管桌面 IDE 已经打开的调试会话；没有伪称人类与模型已经共享同一会话。此版本也未补齐完整 syscall、fxSDK 全命令和自动资源压缩。相关能力应作为独立后端/领域服务扩展，再通过命令目录公布。

验证记录：MCP 实际构建与调试、界面交互与渲染、gint 图形探针。源码包包含探针与测试脚本。外部协议依据见 MCP 官方规范；这些证据没有被扩大为真机全功能认证。
