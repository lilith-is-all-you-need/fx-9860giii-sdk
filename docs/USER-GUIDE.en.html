Build and debug calculator add-ins

Edit C/C++, build G1A files and inspect the actual SuperH program alongside its screen and keypad.

New in 0.2.0

Clear stop reasons and selected stack-frame context, instruction stepping (Ctrl+Alt+F10/F11), breakpoint enable/disable, retained inspector selection, live screen zoom and original-resolution PNG export. Double-click source images in the project tree for a read-only preview with dimensions, transparency and integer zoom; this does not preview converted fxconv objects, fonts or compressed resources.

For LLMs and scripts, launch FxStudio.Agent.exe --stdio. Its stable MCP tool envelope exposes independently versioned commands, asynchronous operations, retry keys, cancellation, event cursors and actual debugger/framebuffer snapshots. See automation contract and connection example. Automation sessions are separate from desktop sessions; no physical device is controlled.

Start offline

Extract the complete distribution and run FxStudio.exe. The desktop runtime is included. The native SDK, GDB and emulator operate without online services. Check the release validation report to see which toolchain components are included and verified.

A simple installation path such as C:\FxStudio is recommended. Project paths may contain Unicode, spaces and apostrophes. Native compilation stages sources in a separate ASCII cache. When the SDK installation path contains Unicode/apostrophes and has no usable short name, the first build creates a verified ASCII SDK cache (about 400 MB extra). Later builds reuse it; changed SDK contents get a new snapshot. The installation does not need to move. Only the build cache itself needs an ASCII path or usable short name, selectable under Tools → Settings. Final artifacts remain in the project folder. The host tested for this release is Windows 10 x64 build 19045.

Build a project

  1. Choose File → New C/C++ project or Open example.
  2. Edit src/main.c or src/main.cpp. Add new translation units to the target in CMakeLists.txt.
  3. Select Debug and press Ctrl+Shift+B. Errors appear in Build output.
  4. ELF and G1A outputs are under .fxstudio/build/Debug/artifacts, with a separate Release folder.

Open an existing fxSDK project through CMakeLists.txt. Project paths in project.fxide.json are relative and move with the project. The backend field accepts auto, native and wsl. Auto prefers the bundled native SDK; WSL requires the separately installed SDK distribution.

For multiple executable targets or application-specific CMake options, add fxide.json:

{"target":"counter","cmake":{"MY_OPTION":"ON"}}

Click calculator keys while the target is running. The preview executes the same G1A that GDB is controlling. Pausing freezes simulated CPU time and preserves its current screen.

Locals and Watch show real GDB values. Double-click a variable to inspect structured children; Set value writes the target. Double-click a call-stack frame to inspect its scope. Breakpoints supports conditions and write/read/access watchpoints. Registers, Memory and Disassembly expose CPU state; MMIO reads are refused to avoid inspection side effects. Expressions can change the target when they assign values or call functions.

Source is read-only during builds/debugging. Saving detects external file changes. Restart rebuilds normal projects; imported binaries restart without rebuilding.

Load an existing build

Debug → Load compiled program opens a .fxdebug.json file. Relative paths resolve against that descriptor. This needs native GDB and the emulator, but no WSL/compiler:

{
  "schemaVersion": 1,
  "name": "My add-in",
  "elf": "artifacts/addin.elf",
  "g1a": "artifacts/addin.g1a",
  "sourceDirectory": "source",
  "sourceMappings": [
    {"from":"/original/build/source","to":"source"}
  ]
}

The ELF and G1A load bytes must match exactly. Optional elfSha256 and g1aSha256 pin both files. Provide the matching source snapshot: binary-pair verification does not authenticate source text. Imported source remains read-only.

Build profiles and deployment

Debug compiles user sources with -Og -g3 -fno-lto. Final linking still uses GCC14.1 LTO to read prebuilt SDK libraries. Their optimized variables may remain unavailable. Release keeps project optimization choices. The stable C++ runtime supports templates/RAII/containers but does not support exceptions or threads; throw/catch is rejected.

Build Release, then File → Export G1A. Transfer that file to the calculator and manually verify menu recognition, startup, display and keys. The SDK runs on the computer; the calculator runs the add-in. No physical device was connected during this implementation.

The emulator is not the full Casio OS. Built-in applications, USB, some peripherals and DSP operations remain unsupported. Its speed is not cycle-exact. Simulation is useful evidence, not proof for every device/OS version. The 2,000,000-byte G1A gate is a conservative project limit.

The C++ template explicitly links stdc++. Existing projects using vector, string or new should use target_link_libraries(your_target stdc++ Gint::Gint). Target tests cover vector/string heap operations and RAII destruction, not every standard-library facility.

Troubleshooting offline

  • Missing executable: check the complete extraction and Settings paths; the app does not need online runtime restoration.
  • Hung WSL: cancel the build. Path conversion times out after 15 seconds. Native mode remains independent; Fx Studio never restarts other distributions automatically.
  • Missing source: correct sourceMappings. Registers, memory and disassembly remain available.
  • Target errors: read the emulator/GDB output. Unsupported execution is reported instead of presenting a successful preview.

Release validation and limits

Examples enable gint_setrestart(1) for direct re-entry on the calculator. The emulator has no OS menu, so EXIT immediately restarts the example; use the IDE Stop button to end the debug session.
