# 实机与会话记录

hardware-results.template.json 是空白记录，任何字段都不代表已通过。
推荐先用 engineering.py hardware-record 绑定待测 G1A 的 SHA256 和字节数，
再填写设备型号、OS、观察时间与每项结果。

状态分为 not_run（没测）、pass（观测成功）、fail（实际失败）、
skip（因前置条件失败而未执行），不能把它们混成一个 FAIL。
例如保留内存申请失败后并没有测试模块窗口，窗口应填 skip。

逐项记录：系统是否识别、启动、正常操作、内存不足后重试、取消后重试、
EXIT 后直接重入、重复会话。次数只写确实完成的次数。
保存输入、报错原文、照片/截图文件名；前后轮不一致时保留每轮差异。

不要求反复把真实设备内存申请到耗尽。本模板并不自动执行内存探针、机器码加载、
系统调用或远程设备控制。设备测试的文件必须与已绑定哈希对应；
重新编译后新建记录，不能沿用上一版的 pass。

建议将源码快照、预算报告、编译产物记录和本记录放在独立的运行目录。
不要附带 .fxstudio/skill/*/bridge.json、私钥、用户工作文件或整个浏览器/VM 配置。
